# Releasing to npm

Five packages, all at the version of the tag: `llm-hops` (the launcher, `npm/llm-hops/`) and
`llm-hops-darwin-arm64`, `llm-hops-darwin-x64`, `llm-hops-linux-arm64`, `llm-hops-linux-x64` (one binary
each, generated by `npm/build.js` from GoReleaser's `dist/`). `make npm` builds them locally into
`dist/npm/`; nothing in this repository publishes from a laptop.

## Every release after the first

Push the tag. `release.yml` builds the tarballs from the released binaries, checks that each has the
version of the tag, and the `npm` job publishes them with trusted publishing (OIDC, environment `npm`,
no token). A tag like `v1.0.0-rc1` is published under the dist-tag `next`, not `latest`.

## The first release, by hand

npm lets a trusted publisher be set only on a package that exists, so the first version of each of the
five packages is published by a person. Do it with the tarballs the release workflow built:

1. Leave the repository variable `NPM_PUBLISH` unset and push the tag (`git tag vX.Y.Z && git push origin
   vX.Y.Z`). The `npm` job is skipped; the run keeps the tarballs as the artifact `npm-packages`.
2. Download and publish them, the platform packages first (`V` is the version without the `v`):

   ```bash
   gh run download RUN_ID --repo YauhenBichel/llm-hops --name npm-packages --dir /tmp/npm-packages
   cd /tmp/npm-packages && npm login
   npm publish ./llm-hops-darwin-arm64-$V.tgz --access public
   npm publish ./llm-hops-darwin-x64-$V.tgz   --access public
   npm publish ./llm-hops-linux-arm64-$V.tgz  --access public
   npm publish ./llm-hops-linux-x64-$V.tgz    --access public
   npm publish ./llm-hops-$V.tgz              --access public
   npx -y llm-hops@$V version
   ```

   These five versions have no provenance statement: npm writes one only for a publish from CI.
3. In GitHub: Settings, Environments, create `npm`. Optional and recommended: limit it to tags `v*` and
   require a reviewer.
4. On npmjs.com, for each of the five packages: Settings, Trusted publishing, GitHub Actions, with
   organization or user `YauhenBichel`, repository `llm-hops`, workflow filename `release.yml`,
   environment name `npm`. Under allowed actions, tick `npm publish` for releases that go out without a
   second step, or leave only `npm stage publish` to approve each one on npmjs.com.
   **A new configuration expires unless it publishes within 2 days**, so do this just before the next tag.
5. Set the repository variable `NPM_PUBLISH` to `publish` or to `stage`, matching step 4, and push the
   next tag within those 2 days.
6. Once a release has gone out this way: in each package's settings choose "Require two-factor
   authentication and disallow tokens".

The source repository is public, so trusted publishing adds the provenance statement by itself; no
`--provenance` flag is needed.
